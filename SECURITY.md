# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in `archr`, please report it to us privately via [GitHub Security Advisories](https://github.com/haquiticos/archr/security/advisories/new).

**Do not** open a public issue to report a vulnerability. Public disclosure may allow attackers to replicate and exploit the issue before we can fix it.

## Reporting a Non-Security Issue

For general bugs, features, or other non-security-related issues, please use the [issue templates](.github/ISSUE_TEMPLATE/) or open a discussion in the [GitHub Discussions](https://github.com/haquiticos/archr/discussions).

## Our Response

We will:
1. Acknowledge your report within 3 business days
2. Investigate the issue within 7 days
3. Work with you to confirm a fix and coordinate disclosure timing

## Fixing the Vulnerability

Once confirmed, we will:
1. Create a patch addressing the vulnerability
2. Apply the patch to the main branch
3. Prepare a security release with the fix
4. Coordinate disclosure according to the severity (e.g., embargo period before public disclosure)

## Vulnerability Disclosure

For critical or high-severity vulnerabilities, we may request an embargo period before public disclosure to allow users to upgrade. For moderate or low-severity issues, we may disclose immediately once fixed.

## Non-Security-Related Bugs

The security policy covers security vulnerabilities only. For non-security bugs (e.g., crashes, incorrect behavior, performance issues), please use the standard issue reporting channels and normal development workflow.

## Attribution

We will attribute fixes in our release notes. If you prefer to remain anonymous, please specify this in your report.

## License Changes for Vulnerability Fixes

We generally do not change the project's license for vulnerability fixes. If there are concerns about a specific fix's licensing implications, please discuss this with us privately.
